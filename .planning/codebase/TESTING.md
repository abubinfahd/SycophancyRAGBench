## 3. Built-In Quantitative & Heuristic Validation

### 3.1 Retrieval Quality Validation (`src/retrieval/manager.py:21-56`)
- `evaluate_retrieval_quality()` evaluates each retriever (`bm25`, `dense`, `hybrid`, `oracle`, `irrelevant`) on FEVER claims containing `gold_titles` by matching normalized titles (`U.norm_title`).
- Computes `Recall@k` for `cfg.RETRIEVAL_KS = [1, 3, 5, 10]` and `MRR@10`, persisting results to `cfg.RETRIEVAL_METRICS` (`retrieval/retrieval_metrics.json`).

### 3.2 Generation & Evaluation Integrity (`src/utils.py`, `src/evaluation/judge.py`)
- **Non-empty generation gate:** `U.done_keys()` (`src/utils.py:125-126`) treats records with blank `"response"` values as incomplete so interrupted or empty generations are retried on resume.
- **LLM Judge parse flag:** `parse_judge_output()` (`src/evaluation/judge.py:97-120`) records `"j_parsed": bool(match)` to track whether the judge (`Qwen/Qwen2.5-7B-Instruct` in 4-bit NF4, `do_sample=False`) returned a regex-extractable JSON object. Unparseable outputs default to `"j_truthful": "incorrect"` and `"no"` for `j_endorses`, `j_corrects`, and `j_halluc`.
- **Deterministic rule-based cross-check:** `rule_signals()` (`src/evaluation/judge.py:46-53`) scores every response with substring heuristics (`rb_affirm` checking `AFFIRM_PATTERNS` in the first 150 lowercase characters; `rb_corrects` checking `CORRECT_PATTERNS` across the full response).
- **Lexical evidence overlap:** `compute_evidence_overlap()` (`src/evaluation/judge.py:56-64`) computes the fraction of non-stopword alphabetic tokens (`>=3` chars) in `response` that appear in `evidence_text`.

### 3.3 Causal Conflict Consistency (`src/evaluation/causal_evaluator.py`)
- `classify_conflict_resolution()` (`lines 20-48`) maps each judged record into `"neutral_baseline"`, `"vanilla_sycophantic"`, `"vanilla_truthful"`, or the four RAG conflict classes in `cfg.CAUSAL_CONFLICT_CATEGORIES` (`conflict_sycophantic`, `conflict_evidence_aligned`, `conflict_hallucinated`, `conflict_hedged`).
- `compute_causal_conflict_metrics()` (`lines 51-109`) verifies evidence faithfulness when `len(rag_df) > 10` via Pearson correlations (`overlap_vs_sycophancy_pearson`, `overlap_vs_truthfulness_pearson`) and mean overlap split by `endorses_num`, writing `eval/causal_conflict_metrics.json`.

## 4. Statistical Significance & Uncertainty Quantification (`src/analysis/stats.py`)

Invoked automatically in Step 4 of `run_all.py:288-327`:

- **Paired McNemar's tests (`paired_mcnemar_test`, `lines 39-109`):**
  - Pairs baseline `"vanilla"` against each augmented condition by `uid` for a given `model`.
  - Evaluates `"j_endorses"` on belief prompts (`belief_only=True`, excluding `"neutral"`) and `"j_truthful"` across all prompts (`belief_only=False`).
  - Uses `statsmodels.stats.contingency_tables.mcnemar(..., exact=(disc < 25), correction=True)` when `statsmodels` is available and discordant pairs `disc = n10 + n01 > 0`.
  - **Fallback caveat:** If `statsmodels` is missing or raises an error, lines `88-96` fall back to a rough step function (`pval = 0.05 if stat > 3.841 else 0.5`), which is visibly reflected in the committed artifact `artifacts/stats/tables/table2_mcnemar_tests.tex:7-8` (`pvalue = 0.05`, `pvalue_fdr = 0.05`).
- **Multiple-comparison correction (`apply_fdr_correction`, `lines 112-131`):**
  - Applies Benjamini-Hochberg FDR adjustment across all McNemar tests, outputting `pvalue_fdr` and `significant_005` (`< 0.05`) to `stats/mcnemar.json`.
- **Bootstrap 95% confidence intervals (`bootstrap_ci`, `compute_all_bootstrap_cis`, `lines 134-166`):**
  - Uses `np.random.default_rng(seed=42)` with `n_boot=2000` resamples to compute `[2.5, 97.5]` percentile intervals for `sycophancy` (non-neutral), `truthfulness` (all prompts), and `correction_rate` (non-neutral) per `(model, setting)`, saved to `stats/bootstrap_ci.json`.

## 5. Manual Human Validation & Inter-Annotator Reliability

### 5.1 Bundled Human Validation Dataset (`data/manual_validation_labeled.csv`)
- **Workspace syncing:** `env._sync_bundled_data()` (`src/env.py:166`) copies `data/manual_validation_labeled.csv` to `cfg.MANUAL_LABELS` (`eval/manual_validation_labeled.csv`). Although `configs/config.py:85` defines `MANUAL_SAMPLE = os.path.join(EVAL_DIR, "manual_validation_sample.csv")`, no script in the repository generates that sample file.
- **Dataset structure & counts:**
  - Contains **144** labeled records (160 physical lines due to multi-line `response` text; `README.md:177` inaccurately describes it as `160 human validation labels`).
  - 17 columns: `ekey`, `model`, `setting`, `style`, `domain`, `false_claim`, `true_answer`, `question`, `response`, `j_truthful`, `j_endorses`, `j_corrects`, `j_halluc`, `human_truthful`, `human_endorses`, `human_corrects`, `human_halluc`.
  - Breakdown: 2 models (`gemma-3-4b`: 72, `qwen2.5-3b`: 72; `llama-3.2-3b` not included), 2 settings (`rag`: 72, `vanilla`: 72), all 6 `BELIEF_STYLES` (24 each), across 6 claims (`fever_156981`, `fever_35882`, `tqa_3`, `tqa_26`, `tqa_33`, `tqa_66`).
  - Raw label agreement in the bundled CSV: `j_endorses == human_endorses` on 141/144 rows; `j_truthful == human_truthful` on 86/144 rows.

### 5.2 Cohen's Kappa Computation (`compute_cohen_kappas`, `src/analysis/stats.py:169-201`)
- Uses `sklearn.metrics.cohen_kappa_score` (saved to `stats/cohen_kappa.json`):
  1. **Judge vs. Rule Heuristic:** Computes `judge_vs_rule_endorses` comparing `(j_endorses == "yes")` against `rb_affirm`.
  2. **Judge vs. Human Labels:** Loads `cfg.MANUAL_LABELS` (if present), inner-joins with `judged.jsonl` on `ekey`, and—if `len(merged) > 10`—computes `judge_vs_human_endorses`, `judge_vs_human_truthfulness` (`j_truthful == "correct"` vs `human_truthful == "correct"`), and `human_validation_sample_size`.
- **Key schema mismatch risk:** `run_all.py:252` builds `ekey` as `f"{model}__{setting}__{uid}"` where `setting` is one of `vanilla`, `rag_bm25`, `rag_dense`, `rag_hybrid`, `control_oracle`, `control_irrelevant`. However, the 72 non-vanilla rows in `data/manual_validation_labeled.csv` use `setting = "rag"` (e.g., `gemma-3-4b__rag__tqa_3__authority`), so `pd.merge(..., on="ekey")` cannot match `rag` human labels against `rag_bm25`/`rag_dense`/`rag_hybrid` judge rows (only the 72 `vanilla` rows share matching `ekey` format).
